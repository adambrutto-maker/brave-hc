## Read-only checker

New `scripts/audit_hockeyos_plan03_release_health.py` accepts four explicit local sources:

- `--task-report`: actual `auto_refresh_last_run.json` from BRUTTECH 1.
- `--verified-feed`: `261017_HTO_Verified_GameLevel_Skater_Attendance.json` generated by the bounded production collector.
- `--published-watch`: historical `widgets/watch.json` from the local HockeyOS publisher checkout.
- `--records`: HTO public `widgets/history-records.json` from the reviewed repository state.

It performs **no network operations or writes**, does not import the production controller, and has no capability to edit HTO, the original workbook, Tasks, public widgets, GitHub or awards. It requires an offset-aware, temporally ordered HTO readback within the same controller run, a receipt not older than two hours, all expected scheduled stages with truthful return codes and summary flag, exactly four currently accepted HTO game identities with known official scores, the 558/119 authoritative record snapshot, and both existing correctly dated native HTO milestone entries.

The classification intentionally distinguishes:

- `processing=PASS`: the scheduled pipeline executed its eight stages successfully.
- `recordWatchSourceState=HISTORICAL_ONLY`: the public milestone panel shows previously published HTO achievements, not live new club records.
- `workbookRelease=HOLD_STALE_WORKBOOK_FINALS`: original workbook saved scores are not reconciled to the HTO completed games.
- `projectionRelease=HOLD_MODEL_RECONCILIATION_PENDING`: the processing step can pass while model publication remains held.
- `watchPublisher=UNCHANGED_SNAPSHOT`: no new Watch JSON publication was performed.
- `websitePublication=NOT_VERIFIED_BY_SCHEDULED_TASK`: GitHub Pages public release is independently verified, not inferred from local task success.
- `nextGameAdmission=NOT_ADMITTED_HTO_3375682`: the planned October 25 game remains out of the four-game collector until its *completed* official boxscore is admitted under a new reviewed mapping.

## Release and rollback

- Merge this checker and its tests only after local QA and review. In `brave-record-source-refresh.yml`, CI runs the 15 synthetic guardrail tests; it does **not** execute the private Windows task checker or expose private computer paths/receipts as public artifacts.
- No live task registration, publisher revision, workbook or HTO mutation is authorized by this package.
- To roll back, revert only the source checker/tests/CI selector and this runbook. Since the code is read-only and standalone, no original runtime state needs restoring.
- A future automated local alert or health card can consume the check **after** acceptance, with private receipt retention, fail-closed input freshness and bounded scheduling.
- A new fifth completed game must trigger a reviewed mapping/test/source-contract expansion. Never silently allow `359 + index`, invent stats, or relax the source chronology.
